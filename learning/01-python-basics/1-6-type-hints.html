1-6 型ヒント — 「この箱には何が入る」という注釈

このレッスンのゴール：name: str や -> dict のような「コロンと矢印の注釈」が読めるようになる。

ASCT は型ヒントを多用しています。これが読めると、コードが「自己説明」してくれます。

🔵 型ヒントとは

型ヒント は、「この変数・引数・返り値には、この種類の値が入りますよ」という 注釈 です。 書いても書かなくてもプログラムは動きますが、書いてあると 読む人に親切 で、間違いも見つけやすくなります。

pythonprice: int = 100              # 🔵 price には int（整数）が入る、という注釈
name: str = "りんご"          # 🔵 name には str（文字列）が入る

重要読み方：変数名 : 型 の コロンの後ろ が型です。「price は int 型」と読みます。

🔵 関数の型ヒント — 入口と出口に注釈

pythondef add_tax(price: float) -> float:   # 🔵 floatを受け取り、floatを返す関数、という宣言
    return price * 1.1
  • price: float … 引数 の型（入口）。「floatを受け取る」
  • -> float … 返り値 の型（出口）。矢印の後ろが「返すもの」。「floatを返す」

重要これが読めると、関数の中身を読まなくても 「何を入れて、何が出てくるか」 が分かります。 忙しいときは、まず型ヒントだけ見て当たりをつけられます。

🔵 よく出る型の一覧

書き方意味
int / float / str / bool整数 / 小数 / 文字列 / 真偽値
dict辞書（{...}）
listリスト（[...]）
list[dict]「辞書を並べたリスト」
list[str]「文字列を並べたリスト」
`int \None`「整数、または何も無い(None)」のどちらか
`CEODecision \EscalationRecord`「CEO決定、またはエスカレーション記録」のどちらか

注意None（ノン）とは：「値が無い」を表す特別な値。int | None は 「整数が入ることもあれば、空っぽのこともある」という意味。| は「または」。

🟢 ASCT の本物のコードで見る

src/orchestrator/ceo.py の13〜15行目。CEOが最終判断を返すメソッドの宣言です：

pythondef resolve(
    self, scenarios: list[dict], event: Event, config: dict   # 🔵 入口：辞書のリスト・イベント・設定
) -> CEODecision | EscalationRecord:                          # 🔴 出口：CEO決定 か エスカレーション のどちらか

中身を1行も読まずに分かること：

  • 入力は「シナリオのリスト（list[dict]）」「イベント（Event）」「設定（dict）」の3つ。
  • 出力は「CEODecision（決定）」または「EscalationRecord（人間に委ねる記録）」。

実務実務での意味：この型ヒントだけで、ASCT の心臓部の設計思想が読めます。 「CEOは、シナリオを見比べて、自分で決める（CEODecision）か、人間にエスカレする（EscalationRecord）か、 どちらかを返す」。あなたが企画した「AIが決めきれないときは人間に委ねる」という思想が、 -> CEODecision | EscalationRecord という1行の出口宣言に表れています。

⚪ 補足：ClassVar や Mapped など見慣れない型

ASCT には Mapped[int]（4章で説明）や ClassVar[list[str]] も出てきます。 これらは「特殊な文脈での型ヒント」です。今は [ ] の中が本体の型 とだけ押さえてください。 Mapped[int] なら「中身は int」、list[str] なら「中身は文字列のリスト」。

✅ 検証ポイント（AIコードを読むとき）

  • 検証宣言と実態が合っているか：-> dict と書いてあるのに、return 5（数字）していたら矛盾＝バグの疑い。
  • 検証None の可能性を見落としていないか：int | None を返す関数の結果を、

そのまま計算に使うとエラーになりうる（None + 1 は不可）。AIが None チェックを忘れる典型バグ。

  • 検証型ヒントを「設計の意図」として読む：CEODecision | EscalationRecord のような

「どちらか」の型は、その関数の役割そのものを語っている。
