1-4 import とモジュール — コードを分けて、持ってくる

このレッスンのゴール：ファイルの先頭に並ぶ import 〜 / from 〜 import 〜 が読めるようになる。

これが読めると「このファイルは、どこの何を使っているか」が分かり、コードを追えるようになります。

🔵 なぜファイルを分けるのか

ASCT は38本の .py ファイルでできています。1本に全部書くと数千行になって、誰も読めません。 そこで 役割ごとにファイルを分け、必要なときに「持ってくる」のです。

  • 1本のファイル = モジュール
  • フォルダにまとめたモジュール群 = パッケージ（例：src/agents/ フォルダは「agentsパッケージ」）

🔵 import の2つの書き方

書き方A：import モジュール名

pythonimport yaml          # 🔵 yaml という道具一式を持ってくる

使うときは yaml.safe_load(...) のように「モジュール名.機能」と書きます。

書き方B：from モジュール import 必要なものだけ

pythonfrom src.config.validator import validate_config   # 🔵 validator の中の validate_config だけ持ってくる

使うときは validate_config(...) と、名前だけで直接呼べます。

重要読み方：from A import B は「Aという場所から、Bを持ってくる」。 これが読めれば、B の定義が A というファイルにあると分かり、追いかけられます。

🔵 src. は何者か

from src.agents import ... の src は、ASCT のソースコードが入った一番上のフォルダの名前です。 src.orchestrator.ceo は「src フォルダ → orchestrator フォルダ → ceo.py ファイル」を ドットでつないだ住所表記です。

src/                       ← src
 └ orchestrator/           ← src.orchestrator
    └ ceo.py               ← src.orchestrator.ceo
       └ class CEOOrchestrator   ← src.orchestrator.ceo.CEOOrchestrator

注意注意：from src.orchestrator.ceo import CEOOrchestrator を読んだら、 「src/orchestrator/ceo.py を開けば CEOOrchestrator の中身が見られる」と分かります。 import は、コードの中の道案内（リンク） だと思ってください。
