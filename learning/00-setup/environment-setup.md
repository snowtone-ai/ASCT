# 環境構築手順書 — 最初の1回だけ

この手順は **最初に1回だけ** やればOKです。一度終われば、次回からは「起動」だけで学習を始められます。

> 🟡 **注意**：途中でエラーが出たら、慌てず **エラーメッセージをそのまま Claude に貼り付けて** ください。
> 「環境構築の手順書の3番でこのエラーが出た」と言えば、原因を特定して直す手伝いをします。

---

## 🔵 そもそも「環境構築」とは？

ASCT は Python という言語で書かれています。これを動かすには、パソコンに
「Python本体」と「ASCTが使う部品（ライブラリ）」をそろえる必要があります。
それをこの手順でやります。料理を始める前に、コンロと食材をそろえる作業だと思ってください。

---

## ✅ 事前チェック：必要なものが入っているか

PowerShell（Windowsの黒い画面。スタートメニューで「PowerShell」と検索）を開いて、
次の2つを **1行ずつ** 打って Enter してください。

```powershell
python --version
```
→ `Python 3.11.x` 以上（3.11、3.12、3.13 のいずれか）が表示されればOK。

```powershell
node --version
```
→ `v18` 以上が表示されればOK（ASCT のセットアップ補助スクリプトが Node を使うため）。

> 🟡 もし「python は認識されていません」と出たら、Python がまだ入っていません。
> [python.org](https://www.python.org/downloads/) からインストールするか、Claude に
> 「Python が入っていないみたい。どうすればいい？」と聞いてください。

## 手順（上から順に、1つずつ）

> 🔴 **重要**：これ以降のコマンドは、すべて **ASCT のプロジェクトフォルダの中** で実行します。
> PowerShell でまずそこへ移動します。

### ステップ 1：プロジェクトフォルダへ移動

```powershell
cd C:\Users\chidj\project\ASCT
```

画面の行頭が `...\ASCT>` になっていれば成功です。

### ステップ 2：仮想環境を作る

```powershell
python -m venv .venv
```

🔵 **これは何？**：`.venv` という専用の「箱」を作っています。
ASCT 用の部品を、パソコン全体ではなくこの箱の中だけに入れることで、
他のプロジェクトと干渉しないようにします。プロジェクトごとの「専用の棚」です。

→ フォルダ内に `.venv` という新しいフォルダができれば成功。

### ステップ 3：仮想環境を「有効化」する

```powershell
.venv\Scripts\Activate.ps1
```

🔵 **これは何？**：作った棚を「いま使う棚はこれ」と指定する操作です。
成功すると、行頭に `(.venv)` と表示されます。これが出ていれば、以降のコマンドは専用の棚の中で動きます。

> 🟡 **注意**：もし「スクリプトの実行が無効になっている」という赤いエラーが出たら、
> 一度だけ次を実行してから、もう一度ステップ3を試してください。
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
> ```

> 🔴 **毎回必要**：この `(.venv)` の有効化は、**PowerShell を開くたびに** 必要です。
> （ステップ1の `cd` と、このステップ3だけは、学習を始めるたびに行います。詳しくは `session-guide.md`。）

### ステップ 4：ASCT が使う部品をインストール

```powershell
pip install -e ".[dev]"
```

🔵 **これは何？**：`pyproject.toml` に書かれた必要な部品（FastAPI、SQLAlchemy など）を
まとめて棚に入れます。`[dev]` は「テストやコード整形の道具も一緒に」という意味です。
たくさんの行が流れますが、最後にエラーがなければ成功。1〜3分かかることがあります。

### ステップ 5：データベースを作って、練習用データを入れる

```powershell
python -m src.seed.generate
```

🔵 **これは何？**：`asct.db` という名前のデータベースファイルを新規作成し、
2社分の架空の会社データ（商品・在庫・売上履歴・イベントなど）を流し込みます。
これがあるおかげで、空っぽではなく「動く本物」を読めます。

→ プロジェクト直下に `asct.db` というファイルができれば成功。

### ステップ 6：サーバーを起動して動作確認

```powershell
uvicorn src.main:app --reload
```

🔵 **これは何？**：ASCT の本体（Web API）を起動します。
`Uvicorn running on http://127.0.0.1:8000` のような表示が出れば成功です。

そのまま **ブラウザで次のURLを開いてください**：

```
http://localhost:8000/docs
```

🟣 **何が見える？**：「Swagger UI」という、APIの一覧画面が出ます。
これは ASCT が外部から受け付けられる「注文の窓口リスト」です。
`POST /api/events`（イベントを送る窓口）などが並んでいれば、すべて正常に動いています。

> ⚪ **補足**：サーバーを止めるときは、PowerShell の画面で `Ctrl` + `C` を押します。

## 困ったときの早見表

| 症状 | 対処 |
|---|---|
| `(.venv)` が行頭に出ない | ステップ3をやり直す。`cd` でフォルダにいるか確認 |
| `ModuleNotFoundError` | ステップ4のインストールが未完了。`(.venv)` 有効化後に再実行 |
| `asct.db` がない | ステップ5を実行 |
| ポート 8000 が使用中 | 別の起動が残っている。PowerShell で `Ctrl+C` 後に再起動 |
| 何をどう直せばいいか分からない | エラー全文を Claude に貼って質問する |
